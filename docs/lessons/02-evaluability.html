Designing for Evaluability

Instrument the agent before it takes traffic, so that every run leaves behind a trace you can actually answer questions from.

01 Objective

You can design a trace schema by working backwards from the questions you will need to answer, rather than forwards from what happens to be convenient to log.

02 The failure this prevents

Instrumentation added after an agent is already running captures whatever was easy to capture. Three weeks later something breaks, you open the logs, and the one field that would settle it is not there. You add it, ship, and wait for the bug to happen again.

The expensive version of this is a regression you cannot attribute. Quality drops, four things changed that week, and no trace records which prompt version produced which run. Now you are bisecting production by memory. A twelve character hash on every model call would have answered it in a minute, and it costs nothing to add on day one.

03 Concepts
Span
One unit of work with a start, an end, a status, and a parent. Model calls, tool calls, guard decisions, and handoffs are all spans. A trace is the tree they form.
Why a tree and not a log
A flat log can tell you what happened. A tree tells you what happened inside what. "The refund failed" and "the refund failed inside the retry that followed the first denial" are different facts, and only one of them is actionable.
Attribution
The property that lets you connect an observed behaviour to the change that caused it. In practice: a prompt hash, a model name, and a code version on every span that could be affected by them.
Evaluability
A design property, decided up front, that determines whether the system can be measured at all. A system that is not evaluable is not made evaluable by wanting it harder later. It is made evaluable by changing it.
Denials as evidence
A trace that only records successes cannot distinguish an attack that was blocked from an attack that never happened. Both look like silence.

Two clocks, and they are not the same clock

The world clock in this repository is frozen at 2026-08-01, because return window arithmetic must not drift and rot the corpus. Trace timestamps are real wall clock, because they record what actually happened during a run. Conflating these is a mistake in both directions: a frozen trace clock makes latency meaningless, and a live world clock makes yesterday's expected answers wrong today.

04 Mental model

Design the schema by writing the questions first, then the field that answers each one.

Question you will be askedField that answers itCost of not having it
Which change caused this regression?prompt_hash on every model callBisecting production from memory
Which step is burning the budget?cost_usd per spanYou can only cut the whole agent
Was this attack blocked or absent?denial spans, always recordedSecurity theatre
Did it consult the source of truth?tool call spans with argsCannot tell recall from lookup
Why did it stop?terminal event on the root spanTimeouts look like short chats

Every row is a question somebody will genuinely ask you. If a field on your schema does not answer one, consider whether it is earning its place; if a question in your head has no field, that is the gap to close before launch.

07 Traps
  • Check that you can attribute a regression to a change. If two prompt versions produce identically-shaped traces, you have logging but not attribution.
  • Check that cost and latency exist per span, not just per session. A session total cannot tell you what to cut, which makes every optimisation a guess.
  • Check what a timeout looks like. If an agent that ran out of steps produces the same trace shape as one that finished early, you will misclassify it forever.
  • Check that you are not logging the whole prompt on every span. Traces get expensive and, worse, they start carrying customer data into systems that were never scoped to hold it.
  • Check that sampling does not drop the interesting traces. Sample the boring ones. Keep every denial, every error, and every escalation.
08 Self-check
  • Your agent gets slower on Tuesday. Which spans do you look at, and what field tells you whether it is the model or a tool?
  • Why is a permission denial recorded as a span rather than raised as an exception?
  • What breaks if trace timestamps use the frozen world clock instead of wall clock?
  • Name a field you would refuse to put on a span, and say what it would cost you.
