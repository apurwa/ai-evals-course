Three-level success writer

Three runs of the Wayfarer support agent. Judge each one at all three levels before you look at the answer. The point is not to score well. It is to notice that the levels disagree.

What is real here and what is not

The tool calls in these three runs were chosen by a script, not by a language model, so that each one demonstrates a specific disagreement between levels. Everything downstream of the call is real: the permission layer really ran, the database was really queried, the denials are real denials from agent/permissions.py, and the correct refund amounts come from data/world/rules.py. Model-generated traces arrive in Lesson 3. Token counts are placeholders and latency is meaningless at this scale, so neither is shown.

What this was for

read after all three

One run passed everywhere. One reached for an air label on a hazmat item and a refund beyond its authority, was stopped by code both times, recovered, and produced a correct end state. One did nothing forbidden at all and shortchanged a customer by $7.25.

An eval that reads only the final response scores the second run as a success and the third as a success. It is wrong twice, in opposite directions, and its number will look fine.

Notice also what the permission layer did and did not do. It blocked the refund that was too large. It permitted the refund that was too small. Every rule it enforces is about the company's exposure, so it guards one direction only. It is a boundary, not an evaluator, and the third run is what it looks like when a team confuses the two.
